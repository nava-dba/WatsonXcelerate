Scene 1 Hook — The Status Quo 0 – 8 s
▶ Screen

Terminal window open. Run:
ibmcloud schematics workspace list
Show the 40+ workspace list scrolling. Then run:
ibmcloud schematics logs --id <ws-id> > out.log
Open the log file — thousands of raw lines visible.

◆ Narration

"When a Terraform deployment fails on IBM Cloud, this is what you're faced with — thousands of raw log lines, no structure, no signal. Just noise."

Scene 2 The Pain — Manual triage is slow and hard 8 – 20 s
▶ Screen
  • Scroll quickly through the raw log file — show grep commands failing
  • Show the IBM Cloud console Schematics workspace page — failed status, no actionable info
  • Optionally: clock graphic or "45 min" text overlay
◆ Narration

"Engineers spend 45 minutes or more per incident manually searching for the root cause — scrolling through thousands of lines, running greps, context-switching between tools. It's repetitive, error-prone, and requires deep Terraform expertise. Non-technical team members simply can't participate."

⚠ Director Note
Use fast-scroll on the log file to visually communicate the volume problem. Keep this under 12 seconds.
Scene 3 The Solution — Plug-and-play, any IBM Cloud account 20 – 33 s
▶ Screen
  • Show terminal: export IBM_CLOUD_API_KEY=... then python3 scripts/fetch_dc_scheduled_runs_logs.py
  • Pipeline running — show log output scrolling as workspaces are processed
  • Cut to: python3 proxy.py → browser opens to Dashboard
◆ Narration

"Meet WatsonXcelerate — a one-stop, plug-and-play AI log analyzer. Any IBM Cloud account can use it: just provide your API key, and the tool automatically pulls logs from every Schematics workspace in your account — no manual selection, no CLI commands. Our AI pipeline, powered by watsonx.ai, classifies every error in seconds."

Scene 4 Dashboard Walk-through — Instant intelligence 33 – 46 s
▶ Screen
  • Dashboard (screen 1): Show error donut chart — 5 errors, 18 runs, Latest DA Runs list
  • Stability page (screen 2): Click a row — expand error detail with module path + description
  • Analytics page (screen 4): Bar chart — Remote Exec, SSH Connectivity, etc. Filter by date range
◆ Narration

"The IBM Carbon dashboard gives you instant visibility — error categories, affected workspaces, trends over time. Click any run to see the exact root cause, the Terraform module, and a plain-English description. What used to take 45 minutes now takes 3. And for the first time, everyone on the team — technical or not — can understand what went wrong."

  • Show the floating WatsonX Assistant chatbot panel open (screen 5)
  • Type a question: "Why did the vpc-si workspace fail on June 11?"
  • Show the streamed response explaining the Terraform INIT error
  • Final frame: Dashboard home with "IBM Intelligent Log Analyzer" header visible

Critically, your log data never leaves IBM Cloud — the chatbot runs entirely on IBM's Granite model via watsonx.ai, ensuring full data governance and sovereignty. No data sent to external services. Ever. WatsonXcelerate — built with IBM Bob, for everyone."

Recording Tips
  • Record screen at 1920×1080 or 1280×720. The dark Carbon dashboard looks great on video.
  • Record narration separately and mix in post — easier to re-record individual lines.
  • For Scene 2, pre-prepare a trimmed log file so the scrolling shows ~100 lines quickly without waiting.
  • For Scene 5, pre-type the chatbot question off-screen so streaming response appears live on camera.
  • Keep total file under 10 MB — at 720p, 60 s of screen recording is typically 5–8 MB.
